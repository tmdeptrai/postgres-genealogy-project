    \section{Introduction}

    Old documents and records from France contain important information about families and history. Many of these documents are stored in archives. To study and understand this information, we need to organize it in a database. This project focuses on creating a database system for marriage records from the Vendée region. We show how to take messy information and organize it in a clean, useful way.

    \subsection{Dataset Overview}

    We use a file called \texttt{mariages\_L3\_5k.csv} which contains 5,000 marriage records. Each record includes information about two people who got married, their parents, and the place and date of marriage.

    The data has these main parts:

    \begin{itemize}
        \item \textbf{Record Information:} Each record has an ID number and a date
        \item \textbf{Person A Information:} Name of the first person, and names of their mother and father
        \item \textbf{Person B Information:} Name of the second person, and names of their mother and father
        \item \textbf{Location Information:} The city (commune) and region (department) where the marriage happened
    \end{itemize}

    \subsection{Why This Project Is Important}

    When we have many old documents, it is difficult to find information or see patterns. A database makes this easier. Our database has these goals:

    \begin{enumerate}
        \item \textbf{Organization:} Store all the information in one place in a clear way
        \item \textbf{No Duplicates:} Each person should appear only once in the database, even if they appear in many records
        \item \textbf{Correct Information:} Make sure that all relationships between people and places are correct
    \end{enumerate}

    \subsection{Normalization Process}
    % TODO Explain how you transition the initial concepts into a normalized relational schema

    \begin{enumerate}
        \item \textbf{For 1NF:}\newline
              All values are atomic (each cell contains one piece of data).

              Each record is uniquely identified by an Act ID
              => Result: 1NF achieved

        \item \textbf{For 2NF:} \newline
              \textbf{Problem}: Repetition of data for parents, towns, and departments leads to redundancy.

              \textbf{Solution}: Separate entities so that every non-key attribute depends on the whole primary key

              \textbf{Resulting FDs}:
              \begin{verbatim}- Act_ID → (Type, Date, View_Num, Commune_ID, Person_A_ID, Person_B_ID)
- Person_ID → (Last_Name, First_Name, Father_ID, Mother_ID)
- Commune_ID → (Name, Dept_Code)
            \end{verbatim}
              => Result: 2NF achieved

        \item \textbf{For 3NF:} \newline
              \textbf{Problem}:
              \begin{itemize}
                  \item Transitive Dependency: The Department depended on the Town, which depended on the Act.
                  \item Parental names depended on the person
              \end{itemize}
              \textbf{Solution}:
              \begin{itemize}
                  \item Extracted Department into a standalone table to enforce valid codes (44, 49, 79, 85).
                  \item Established foreign keys \verb|(father_id, mother_id)| within the Person table to handle lineage without repeating names.
              \end{itemize}
              \textbf{Final FDs}:
              \begin{verbatim}Act_ID → (Act_Type, Date, View_Num, Commune_ID, Person_A_ID, Person_B_ID)
Person_ID → (Last_Name, First_Name, Father_ID, Mother_ID)
Commune_ID → (Commune_Name, Dept_Code)
Dept_Code → (Valid_Codes: 44, 49, 79, 85)
            \end{verbatim}
              => Result: 3NF achieved
    \end{enumerate}

    \section{Genealogical Queries \& Results}
    \subsubsection*{1. The number of communes per department}
    \begin{verbatim}
    SELECT dept_code, COUNT(*) AS total_town
    FROM town
    GROUP BY dept_code;
    \end{verbatim}

    \subsubsection*{2. The number of acts in Luçon}
    \begin{verbatim}
    SELECT COUNT(*)
    FROM act
    JOIN town ON act.town_id = town.id
    WHERE town.name ~* '^LUÇON$';
    \end{verbatim}

    \subsubsection*{3. The number of marriage contracts before 1855}
    \begin{verbatim}
    SELECT COUNT(*)
    FROM act
    WHERE act.act_type = 'Contrat de mariage'
    AND act.act_date < '1855-01-01';
    \end{verbatim}

    \subsubsection*{4. The town with the highest number of marriage publications}
    \begin{verbatim}
    SELECT town.name, COUNT(*) AS total_publications
    FROM act
    JOIN town ON act.town_id = town.id
    WHERE act.act_type = 'Publication de mariage'
    GROUP BY town.name
    ORDER BY total_publications DESC
    LIMIT 1;
    \end{verbatim}

    \subsubsection*{5. The date of the first and last records}
    \begin{verbatim}
    SELECT MIN(act_date) as first_act, MAX(act_date) as last_act
    FROM act;
    \end{verbatim}
